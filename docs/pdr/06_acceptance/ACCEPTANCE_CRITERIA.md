# Acceptance Criteria

## Package-Level Acceptance

- [ ] `getdesign.md` exists and explains GO-mode behavior.
- [ ] PDR explains product goal, MVP, requirements, risks, and success metrics.
- [ ] Implementation queue exists with owners and stop conditions.
- [ ] Agent handoffs exist for major roles.
- [ ] Design token requirements are documented.
- [ ] CSS library structure is documented.
- [ ] Claude Design bridge exists.
- [ ] OpenArt prompt library exists.
- [ ] QA checklist exists.
- [ ] Original scaffold is preserved under `implementation_seed/`.

## Design Output Acceptance

- [ ] Uses approved visual language.
- [ ] Uses tokens or explains why not.
- [ ] Has clear component/asset purpose.
- [ ] Avoids visual clutter.
- [ ] Has accessible contrast or flags contrast risk.
- [ ] Is reusable, not one-off.
- [ ] Includes next action.
